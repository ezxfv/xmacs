# 自定义模块组织结构

本目录包含了按功能分类的doom emacs自定义模块，将原本分散在根目录的包和配置进行了彻底的模块化重构。

## 重构完成状态

✅ **重构完成** - 所有零散的配置和包都已经按功能分类组织到对应模块中
✅ **自动加载** - 在 `config.el` 中默认启用所有模块，用户可通过注释禁用
✅ **工具函数分离** - 原 `+func.el` 中的函数已分配到各模块的 `utils.el`
✅ **配置清理** - 根目录不再有 `+func.el`, `+misc.el`, `+ui.el`, `packages.el` 等配置文件

## 模块列表

### 1. lang - 编程语言支持
- **包含功能**: 所有编程语言相关的配置和工具
- **主要配置**: LSP设置、TreeSitter、DAP调试、Go/Rust/Python语言配置
- **工具函数**: LSP性能优化函数（lsp-booster）
- **用途**: 统一管理所有编程语言的开发环境配置

### 2. editor-tools - 编辑增强工具
- **包含功能**: 编辑器增强工具和文本处理工具
- **主要包**: smart-hungry-delete, move-text, visual-regexp, crux, string-inflection, thing-edit
- **工具函数**: move-to-end-of-line 等编辑辅助函数
- **用途**: 提供更智能的文本编辑、删除、搜索替换等功能

### 3. chinese - 中文支持
- **包含功能**: 中文输入法和中文字体优化
- **主要包**: pangu-spacing, cnfonts, valign, pyim配置
- **用途**: 中文输入法配置、中文字体调整、中文排版优化

### 4. search-nav - 搜索和导航
- **包含功能**: 高级搜索和项目导航工具
- **主要包**: color-rg, consult-projectile
- **用途**: 增强项目内搜索和文件导航功能

### 5. knowledge - 知识管理
- **包含功能**: 知识管理、书签系统、LaTeX和PDF支持
- **主要包**: org-roam-ui, org-roam-bibtex, bookmark+, org-download, LaTeX相关包
- **用途**: org-roam知识图谱、文献管理、书签系统、学术写作支持

### 6. ui-theme - UI和主题
- **包含功能**: 界面美化、主题和显示增强
- **主要包**: doom-nano-modeline, crosshairs
- **工具函数**: Tab组管理、切换函数
- **配置内容**: GUI/终端环境适配、字体设置、WSL优化
- **用途**: 界面美化、模式行定制、光标辅助显示、环境适配

### 7. dev-utils - 开发辅助工具
- **包含功能**: 开发调试和统计工具
- **主要包**: gotest, keyfreq, exec-path-from-shell
- **工具函数**: SSH连接管理、vterm增强
- **用途**: Go语言测试、快捷键统计、环境变量同步、SSH管理

### 8. codeium - AI代码补全
- **包含功能**: AI辅助编程
- **主要包**: codeium, codeium-overlay
- **用途**: 智能代码补全和建议

### 9. english - 英语辅助
- **包含功能**: 英语学习和词典工具
- **主要包**: sdcv, deno-bridge
- **用途**: 英语词典查询、翻译辅助

## 模块结构

每个模块都包含：
- `packages.el`: 定义该模块需要的包
- `config.el`: 包含该模块的配置和快捷键设置
- `utils.el`: 模块相关的工具函数（如有需要）
- 语言模块还包含各语言的独立配置文件（如 `+go.el`, `+rust.el` 等）

## 使用方法

1. 所有模块在 `init.el` 中的 `:x` 部分都已启用
2. 所有模块在 `config.el` 中都已默认加载
3. 如需禁用某个模块，在 `config.el` 中注释对应的 `(when (modulep! :x module-name))` 块
4. 运行 `doom sync` 同步配置
5. 重启 Emacs 或运行 `doom/reload`

## 自定义配置

- 每个模块的配置都在其 `config.el` 中
- 如需修改某个模块的配置，直接编辑对应模块目录下的 `config.el` 文件
- 模块间的依赖关系已经合理设置，无需手动管理加载顺序
- 工具函数都在对应模块的 `utils.el` 中，会被自动加载

## 优势

- **高度模块化**: 每个功能领域都有独立的模块
- **易于维护**: 配置分散到各个模块，更容易管理和调试
- **可选择性**: 可以根据需要启用或禁用特定模块
- **清晰结构**: 每个模块的功能和用途都很明确
- **函数分离**: 工具函数按功能分组，避免命名冲突
- **配置集中**: 根目录配置文件大幅简化，只保留核心配置
